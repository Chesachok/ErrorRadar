# Техническая документация Error Radar

## 1. Назначение

Error Radar — расширение для Visual Studio Code, которое представляет диагностики редактора в виде дерева в панели Explorer. Его задача — упростить просмотр диагностических сообщений в файлах проекта и переход к месту, на которое указывает конкретное сообщение.

Расширение использует готовый механизм диагностики VS Code. Оно не анализирует синтаксис языков независимо от установленных инструментов.

## 2. Функциональные требования

1. Показывать файлы, для которых VS Code опубликовал одну или несколько диагностик.
2. Группировать диагностики по файлам.
3. Показывать количество диагностик у каждого файла.
4. Для каждой диагностики показывать сообщение, номер строки и значок, соответствующий серьёзности.
5. Обновлять дерево после события изменения диагностик.
6. По нажатию на диагностику открывать соответствующий документ и перемещать редактор к диапазону диагностики.
7. Предоставлять команду подсчёта ошибок, предупреждений и информационных сообщений активного файла.

## 3. Архитектура

Расширение работает внутри Extension Host — среды выполнения расширений VS Code. В `package.json` объявляются метаданные, команды и представление панели. В `extension.js` реализуется логика.

Основные компоненты:

- **VS Code Diagnostics API** — источник диагностик, опубликованных редактором и языковыми расширениями.
- **DiagnosticsProvider** — преобразует диагностики в структуру дерева.
- **Tree View (Error Radar)** — отображает файлы и сообщения в Explorer.
- **Обработчик `onDidChangeDiagnostics`** — реагирует на изменения диагностик и запрашивает обновление дерева.
- **Команда `error-radar.openDiagnostic`** — открывает документ и переводит редактор к выбранной диагностике.
- **Команда `error-radar.checkDiagnostics`** — подсчитывает диагностические сообщения активного файла.

## 4. Основные структуры данных

### 4.1. Объект файла

Для узла файла используется объект следующего вида:

```javascript
{
    type: 'file',
    uri,
    diagnostics
}
```

- `type` определяет тип узла дерева;
- `uri` идентифицирует файл;
- `diagnostics` содержит массив диагностик этого файла.

### 4.2. Объект диагностики

Для узла отдельного сообщения используется объект:

```javascript
{
    type: 'diagnostic',
    uri: element.uri,
    diagnostic
}
```

Поле `diagnostic` содержит объект VS Code Diagnostic. В частности, используются его поля `message`, `range` и `severity`.

Различие между `diagnostics` и `diagnostic` важно: первое — массив сообщений файла, второе — одна диагностика.

### 4.3. Массив файлов

В `getChildren()` создаётся массив `files`. В него добавляются только файлы, у которых массив диагностик не пуст. Это позволяет не отображать в панели все файлы проекта без необходимости.

### 4.4. Подсчёт категорий

В команде `error-radar.checkDiagnostics` используются числовые счётчики `errors`, `warnings` и `information`. Цикл проходит по диагностическим сообщениям активного файла и увеличивает соответствующий счётчик в зависимости от `diagnostic.severity`.

## 5. Описание методов и функций

### `DiagnosticsProvider.constructor()`

**Назначение:** инициализирует механизм уведомления дерева об изменениях.

Создаёт `vscode.EventEmitter` и сохраняет его событие в `onDidChangeTreeData`. VS Code использует это событие, чтобы узнать, когда нужно повторно запросить данные дерева.

### `DiagnosticsProvider.refresh()`

**Назначение:** сообщает VS Code, что содержимое дерева изменилось.

Вызывает `this._onDidChangeTreeData.fire(undefined)`. Передача `undefined` означает, что требуется обновить всё дерево, а не только один конкретный узел. Сам метод не ищет диагностики и не изменяет их — он отправляет сигнал обновления.

### `DiagnosticsProvider.getTreeItem(element)`

**Вход:** объект узла файла или диагностики.

**Выход:** объект `vscode.TreeItem`, который VS Code может показать в дереве.

Если `element.type === 'file'`, метод формирует строку с именем файла и количеством диагностик, задаёт значок ресурса и состояние раскрытия. Если передана диагностика, метод показывает текст сообщения, номер строки, подсказку и значок серьёзности. Для сообщения назначается команда `error-radar.openDiagnostic`, которой передаётся исходный объект диагностики.

### `DiagnosticsProvider.getChildren(element)`

**Вход:** родительский элемент дерева либо `undefined` для корневого уровня.

**Выход:** массив дочерних объектов.

Алгоритм:
1. Если передан файловый узел, метод преобразует его массив диагностик в объекты узлов типа `diagnostic`.
2. Если передан другой существующий узел, возвращает пустой массив.
3. Если `element` отсутствует, получает диагностики через `vscode.languages.getDiagnostics()`, пропускает файлы без сообщений и возвращает список файловых узлов.

Метод не создаёт `TreeItem`. Он возвращает объекты данных, которые затем преобразуются методом `getTreeItem()`.

### `activate(context)`

**Назначение:** точка входа расширения при активации.

Метод:
1. создаёт `DiagnosticsProvider`;
2. регистрирует представление `errorRadar.diagnostics` в Explorer;
3. подписывается на событие `vscode.languages.onDidChangeDiagnostics`;
4. регистрирует команду перехода к диагностике;
5. регистрирует команду подсчёта диагностик активного файла;
6. добавляет управляемые ресурсы в `context.subscriptions`, чтобы VS Code мог корректно освободить их при деактивации.

### Команда `error-radar.checkDiagnostics`

**Назначение:** показывает краткую статистику диагностики активного файла.

Если редактор не открыт, выводится информационное сообщение. Иначе команда получает диагностики документа, проходит по массиву и подсчитывает:
- `Error` — ошибки;
- `Warning` — предупреждения;
- `Information` и `Hint` — информационные сообщения.

После подсчёта результат показывается через `vscode.window.showInformationMessage()`.

### `deactivate()`

Функция вызывается при деактивации расширения. В текущей реализации отдельные действия не требуются, поэтому функция оставлена пустой.

## 6. Последовательность обновления дерева

1. Языковой инструмент или VS Code публикует обновлённые диагностики.
2. Срабатывает событие `vscode.languages.onDidChangeDiagnostics`.
3. Обработчик вызывает `provider.refresh()`.
4. Провайдер отправляет событие `onDidChangeTreeData`.
5. VS Code повторно запрашивает узлы через `getChildren()`.
6. Данные преобразуются в визуальные элементы методом `getTreeItem()`.

Это событийная модель: расширение не опрашивает диагностики в бесконечном цикле, а реагирует на уведомления VS Code.

## 7. Ограничения

- Расширение отображает диагностики, которые доступны через VS Code API.
- Обнаружение проблем зависит от установленных языковых расширений и их настроек.
- Некоторые ошибки выполнения программы не выявляются статически.
- Расширение не исправляет ошибки автоматически.
- Полное обновление дерева может приводить к изменению состояния раскрытия узлов в интерфейсе.
